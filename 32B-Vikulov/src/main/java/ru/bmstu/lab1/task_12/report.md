# Задача 12. Пара с заданной суммой

**Студент:** Викулов Петр, ИУ3-32Б · **ЛР 1** · **Баллы:** 1 · **Решение:** [`PairWithSum.java`](PairWithSum.java) · **Тесты:** [`PairWithSumTest.java`](../../../../../../test/java/ru/bmstu/lab1/task_12/PairWithSumTest.java)

## Условие

**Вход:** массив из n целых чисел и число s.  
**Выход:** индексы i < j, для которых a_i + a_j = s. Если пар несколько — вывести пару с наименьшим i, а при равенстве — с наименьшим j. Если пары нет — вывести `-1 -1`.  
**Сложность:** средняя

## Формат ввода-вывода

- **Ввод:** `n`, затем `n` целых чисел, затем `s`. Числа разделяются пробелами или переводами строк.
- **Вывод:** индексы `i j` (`i < j`) или `-1 -1`.

Пример запуска:

```text
ввод:
3
-1 2 5
4

вывод:
0 2
```

## Идея решения и выбор структуры данных

Наивное решение перебирает все пары, это `O(n²)`. Здесь используется хеш-таблица
`HashMap<Long, Integer>` «значение → **последний** индекс этого значения».

1. Первым проходом заполняем таблицу. Если значение повторяется, в таблице остаётся самый правый индекс.
2. Вторым проходом идём по `i = 0, 1, 2, …` и вычисляем дополнение `s − a[i]`. Пара с этим `i` существует
   тогда и только тогда, когда дополнение встречается **правее** `i`, то есть его последний индекс `> i`.
   Первое подходящее `i` и есть наименьшее.
3. Для найденного `i` ищем **наименьший** `j` простым проходом вправо до первого `a[j] = s − a[i]`.
   Этот проход выполняется один раз, поэтому общую оценку `O(n)` он не портит.

Почему хранится последний индекс, а не первый: нужен ответ на вопрос «есть ли такой элемент правее `i`»,
и на него отвечает именно последнее вхождение.

Ключ имеет тип `long`, а дополнение считается в `long`: при `s` и `a[i]` около `±2·10⁹` разность
не помещается в `int`.

**Граничные случаи:** элемент нельзя складывать сам с собой (`a[i] + a[i] = s` без второго такого элемента);
несколько пар (выбор наименьшего `i`, затем наименьшего `j`); сумма вне диапазона `int`.

## Асимптотика — [`PairWithSum.java`](PairWithSum.java#L32-L53)

```java
33:        Map<Long, Integer> lastIndex = new HashMap<>();
34:        for (int i = 0; i < values.length; i++) {
35:            lastIndex.put((long) values[i], i);
36:        }
37:        for (int i = 0; i < values.length; i++) {
38:            long complement = sum - values[i];
39:            Integer last = lastIndex.get(complement);
40:            if (last != null && last > i) {
41:                return new int[] {i, firstIndexAfter(values, i, complement)};
42:            }
43:        }
44:        return NO_PAIR.clone();
...
48:        int j = from + 1;
49:        while (values[j] != target) {
50:            j++;
51:        }
```

| Строки | Стоимость | Раз | Вклад |
|--------|-----------|-----|-------|
| 33 | O(1) | 1 | O(1) |
| 34–35 — `HashMap.put` | O(1) в среднем | n | O(n) |
| 37–40 — `HashMap.get` и сравнение | O(1) в среднем | ≤ n | O(n) |
| 41 → 48–51 `firstIndexAfter` | O(n) (≤ n − i − 1 шагов) | **≤ 1** (сразу `return`) | O(n) |
| 44 | O(1) | ≤ 1 | O(1) |

**Время:** `O(n) + O(n) + O(n) = O(n)` в среднем. Строка 41 вызывает линейный поиск, но всего один раз,
потому что сразу после него метод завершается. Поэтому вложенности `n · n` нет.
В худшем случае `HashMap` (все ключи в одной корзине) строки 35 и 39 стоят `O(log n)`, потому что Java 8+
превращает переполненную корзину в дерево. Это даёт `O(n log n)`.
Для сравнения: перебор всех пар двумя вложенными циклами — `n(n−1)/2 = O(n²)`.
**Память:** `lastIndex` хранит до `n` записей, это `O(n)`.
