# Задача 38. Циклический сдвиг влево

**Студент:** Викулов Петр, ИУ3-32Б · **ЛР 1** · **Баллы:** 2 · **Решение:** [`RotateLeft.java`](RotateLeft.java) · **Тесты:** [`RotateLeftTest.java`](../../../../../../test/java/ru/bmstu/lab1/task_38/RotateLeftTest.java)

## Условие

**Вход:** массив из n целых чисел и число k.  
**Выход:** массив, циклически сдвинутый влево на k позиций.  
**Требование:** O(n), O(1) доп. памяти (через тройной разворот).  
**Сложность:** средняя

## Формат ввода-вывода

- **Ввод:** `n`, `n` чисел, затем `k`. Числа разделяются пробелами или переводами строк.
- **Вывод:** массив, циклически сдвинутый влево на `k`.

Пример запуска:

```text
ввод:
3
1 2 3
1

вывод:
2 3 1
```

## Идея решения и выбор структуры данных

Тройной разворот, как требует условие (`O(n)` по времени, `O(1)` по памяти):

1. развернуть первые `k` элементов;
2. развернуть остальные `n − k`;
3. развернуть весь массив.

Пример для `k = 2`: `1 2 3 4 5 → 2 1 | 5 4 3 → 3 4 5 1 2`.

Почему это работает: массив имеет вид `A B`, где `|A| = k`. После шагов 1–2 получается `Aᴿ Bᴿ`. Разворот
целиком даёт `(Aᴿ Bᴿ)ᴿ = B A`, а это и есть сдвиг влево на `k`.

Перед разворотами сдвиг нормализуется: `k = ((k mod n) + n) mod n`. Сдвиг на `n` ничего не меняет, поэтому
`k > n` сводится к остатку. Отрицательный `k` трактуется как сдвиг вправо. Без нормализации индексы вышли бы
за границы массива.

## Асимптотика — [`RotateLeft.java`](RotateLeft.java#L25-L43)

```java
31:        int k = (int) (((shift % n) + n) % n);
32:        reverse(values, 0, k - 1);
33:        reverse(values, k, n - 1);
34:        reverse(values, 0, n - 1);
...
38:        while (from < to) {
39:            int tmp = values[from];
40:            values[from++] = values[to];
41:            values[to--] = tmp;
42:        }
```

Один вызов `reverse` на отрезке длины `L` выполняет тело цикла (строки 39–41) `⌊L/2⌋` раз:
каждая итерация сближает `from` и `to` на 2.

| Строки | Длина отрезка | Итераций 39–41 | Вклад |
|--------|---------------|----------------|-------|
| 31 | — | — | O(1) |
| 32 | k | ⌊k/2⌋ | O(k) |
| 33 | n − k | ⌊(n − k)/2⌋ | O(n − k) |
| 34 | n | ⌊n/2⌋ | O(n) |

**Время:** `k/2 + (n − k)/2 + n/2 = n` обменов, `O(n)`. Строка 31 приводит `k` к `[0, n)`, поэтому
даже при `k ≫ n` работа не растёт. Наивный сдвиг «по одной позиции `k` раз» стоил бы `O(n · k)`.
**Память:** только `tmp`, `from`, `to`, это `O(1)`.
