# Задача 33. Количество инверсий

**Студент:** Викулов Петр, ИУ3-32Б · **ЛР 1** · **Баллы:** 2 · **Решение:** [`Inversions.java`](Inversions.java) · **Тесты:** [`InversionsTest.java`](../../../../../../test/java/ru/bmstu/lab1/task_33/InversionsTest.java)

## Условие

**Вход:** массив из n целых чисел.  
**Выход:** количество пар (i, j) таких, что i < j и a_i > a_j.  
**Требование:** O(n log n) (через модификацию сортировки слиянием).  
**Сложность:** высокая

## Формат ввода-вывода

- **Ввод:** `n`, затем `n` целых чисел. Числа разделяются пробелами или переводами строк.
- **Вывод:** число пар `i < j` с `a[i] > a[j]`.

Пример запуска:

```text
ввод:
4
2 4 1 3

вывод:
3
```

## Идея решения и выбор структуры данных

Перебор всех пар стоит `O(n²)`, а условие требует `O(n log n)`. Поэтому используется модификация сортировки
слиянием.

Массив рекурсивно делится пополам. Инверсии бывают трёх видов: обе позиции в левой половине, обе в правой,
или одна слева, а другая справа. Первые два вида считаются рекурсивно. Третий считается **во время слияния**
уже отсортированных половин: если текущий элемент правой половины `a[j]` меньше текущего элемента левой
`a[i]`, то он меньше и **всех** оставшихся элементов левой половины `a[i..mid)`. Значит, он образует сразу
`mid − i` инверсий. Ответ прибавляется одной операцией, без перебора.

Решения по реализации:
- один общий буфер `buffer` создаётся заранее и передаётся в рекурсию, а не выделяется на каждом уровне;
- сортируется **копия** массива, вход не меняется (это проверяет тест);
- ответ хранится в `long`: при `n = 10⁵` инверсий может быть до `n(n − 1)/2 ≈ 5·10⁹`, а это больше `int`;
- при равенстве (`<=`) первым берётся левый элемент, поэтому равные элементы инверсией не считаются.

## Асимптотика — [`Inversions.java`](Inversions.java#L26-L63)

```java
27:        int[] work = values.clone();
28:        int[] buffer = new int[values.length];
...
34:        if (to - from < 2) {
35:            return 0;
36:        }
37:        int mid = (from + to) >>> 1;
38:        long inversions = sortAndCount(values, buffer, from, mid) + sortAndCount(values, buffer, mid, to);
39:        return inversions + mergeAndCount(values, buffer, from, mid, to);
...
47:        while (i < mid && j < to) {
48:            if (values[i] <= values[j]) {
49:                buffer[k++] = values[i++];
50:            } else {
51:                inversions += mid - i;
52:                buffer[k++] = values[j++];
53:            }
54:        }
55:        while (i < mid) {
56:            buffer[k++] = values[i++];
57:        }
58:        while (j < to) {
59:            buffer[k++] = values[j++];
60:        }
61:        System.arraycopy(buffer, from, values, from, to - from);
```

Пусть `len = to − from` — длина отрезка в одном вызове.

| Строки | Стоимость | Раз за вызов | Вклад за вызов |
|--------|-----------|--------------|----------------|
| 34, 37 | O(1) | 1 | O(1) |
| 38 — два рекурсивных вызова | T(len/2) | 2 | 2T(len/2) |
| 49 / 52 / 56 / 59 | O(1) | суммарно len (каждая итерация увеличивает `k`) | O(len) |
| 51 — подсчёт инверсий | O(1) | ≤ len | O(len) |
| 61 — копирование | O(len) | 1 | O(len) |

Получаем рекуррентное соотношение `T(n) = 2T(n/2) + c·n`, `T(1) = O(1)`.
По основной теореме (`a = 2, b = 2, f(n) = Θ(n) = Θ(n^{log₂2})`) — **`T(n) = Θ(n log n)`**.
То же через дерево рекурсии: на уровне `d` есть `2^d` отрезков длины `n/2^d`, их суммарная длина `n`, и строки
47–61 на уровне выполняют `O(n)` работы. Уровней `⌈log₂ n⌉`, итого `O(n log n)`.

Почему строка 51 корректна за `O(1)`: половины `[from, mid)` и `[mid, to)` уже отсортированы. Если
`values[i] > values[j]`, то `values[j]` меньше всех `values[i..mid)`. Это `mid − i` инверсий за раз,
без перебора.

**Память:** `work` и `buffer` (строки 27–28) по `n` элементов, плюс стек рекурсии глубиной `⌈log₂ n⌉`.
Итого `O(n)`.
