# Задача 20. Сортировка подсчётом

**Студент:** Викулов Петр, ИУ3-32Б · **ЛР 1** · **Баллы:** 2 · **Решение:** [`CountingSort.java`](CountingSort.java) · **Тесты:** [`CountingSortTest.java`](../../../../../../test/java/ru/bmstu/lab1/task_20/CountingSortTest.java)

## Условие

**Вход:** массив из n целых чисел.  
**Выход:** массив, отсортированный по неубыванию.  
**Требование:** реализовать сортировку подсчётом.  
**Сложность:** средняя

## Формат ввода-вывода

- **Ввод:** `n`, затем `n` целых чисел. Числа разделяются пробелами или переводами строк.
- **Вывод:** массив по неубыванию.

Пример запуска:

```text
ввод:
3
2 1 1

вывод:
1 1 2
```

## Идея решения и выбор структуры данных

Сортировка подсчётом не сравнивает элементы, а считает, сколько раз встречается каждое значение.

1. Находим `min` и `max`, диапазон `k = max − min + 1`.
2. Заводим массив счётчиков `counts` длины `k`. Значение `v` хранится в ячейке `v − min`: **сдвиг на `min`**
   позволяет сортировать и отрицательные числа.
3. Проходим по `counts` по возрастанию и выписываем каждое значение столько раз, сколько оно встретилось.

Выбор структуры данных: обычный массив `int[]` даёт доступ к счётчику за `O(1)` и обход значений по порядку.
У хеш-таблицы порядка нет, а `TreeMap` вернул бы `log`.

Метод выгоден, когда диапазон `k` сравним с `n`. При огромном диапазоне (например, `−10⁹…10⁹`) массив
счётчиков не поместится в память. Поэтому введено ограничение `MAX_RANGE = 10⁷` (около 40 МБ), и при его
превышении выбрасывается исключение с понятным сообщением, а не `OutOfMemoryError`. Диапазон считается в `long`,
чтобы `max − min` не переполнился.

## Асимптотика — [`CountingSort.java`](CountingSort.java#L30-L54)

```java
36:        for (int value : values) {
37:            min = Math.min(min, value);
38:            max = Math.max(max, value);
39:        }
40:        long range = (long) max - min + 1;
44:        int[] counts = new int[(int) range];
45:        for (int value : values) {
46:            counts[value - min]++;
47:        }
49:        for (int offset = 0; offset < counts.length; offset++) {
50:            for (int c = 0; c < counts[offset]; c++) {
51:                values[position++] = offset + min;
52:            }
53:        }
```

| Строки | Стоимость | Раз | Вклад |
|--------|-----------|-----|-------|
| 36–38 — поиск min/max | O(1) | n | O(n) |
| 44 — выделение `counts` | O(k) | 1 | O(k) |
| 45–46 — подсчёт | O(1) | n | O(n) |
| 49 — внешний цикл | O(1) | k | O(k) |
| 51 — запись | O(1) | Σ counts[offset] = n | O(n) |

Двойной цикл в строках 49–53 **не** даёт `O(n · k)`. Внешний цикл выполняется `k` раз, а внутренний суммарно
по всем итерациям выполняет `Σ counts = n` шагов. Итого `k + n`.
**Время:** `O(n + k)`. **Память:** массив `counts` размера `k`, это `O(k)`. Строки 41–42 ограничивают
`k ≤ 10⁷`, чтобы память не взрывалась при больших значениях.
