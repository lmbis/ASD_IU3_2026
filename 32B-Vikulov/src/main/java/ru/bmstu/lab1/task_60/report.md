# Задача 60. Острова из единиц

**Студент:** Викулов Петр, ИУ3-32Б · **ЛР 1** · **Баллы:** 3 · **Решение:** [`Islands.java`](Islands.java) · **Тесты:** [`IslandsTest.java`](../../../../../../test/java/ru/bmstu/lab1/task_60/IslandsTest.java)

## Условие

**Вход:** бинарная матрица n x m, состоящая из 0 и 1.  
**Выход:** количество «островов» — групп связанных единиц (связь по горизонтали и вертикали, не по диагонали).  
**Требование:** поиск в глубину (DFS) или в ширину (BFS).  
**Сложность:** высокая

## Формат ввода-вывода

- **Ввод:** `n m`, затем матрица `n × m` из 0 и 1. Числа разделяются пробелами или переводами строк.
- **Вывод:** количество островов (связь по горизонтали и вертикали).

Пример запуска:

```text
ввод:
2 3
1 0 1
1 0 1

вывод:
2
```

## Идея решения и выбор структуры данных

Задача о числе компонент связности в графе: вершины — клетки с единицами, рёбра — соседство по горизонтали
и вертикали.

Перебираем все клетки. Встретив единицу, которая ещё не посещена, увеличиваем счётчик островов и запускаем
**поиск в глубину** (DFS), который помечает весь остров. Каждый остров даёт ровно один запуск.

Решения по реализации:
- **DFS итеративный, с явным стеком** `int[]`. Рекурсивный DFS на матрице из одних единиц уходил бы
  в глубину до `n·m` вызовов и падал бы со `StackOverflowError` (тест на 1000×1000 это проверяет);
- клетка помечается посещённой **в момент добавления в стек**, а не при извлечении. Поэтому каждая клетка
  попадает в стек не больше одного раза, и стека размера `n·m` гарантированно хватает;
- клетка `(r, c)` кодируется в стеке одним числом `r·m + c`, это экономнее массива пар;
- соседи перебираются через массивы смещений `ROW_STEPS` и `COLUMN_STEPS`, без четырёх одинаковых блоков кода;
- посещённые клетки отмечаются в отдельном массиве `visited`, входная матрица не портится.

Ключевое наблюдение: клетка помечается `visited = true` **в момент добавления в стек** (строки 53/64),
а добавляется только непомеченная (строка 63 → 73). Значит, каждая клетка попадает в стек не больше
одного раза за всё время работы, по всем вызовам `markIsland` вместе.

| Строки | Стоимость | Раз (за всё время) | Вклад |
|--------|-----------|--------------------|-------|
| 35, 36 — выделение | O(nm) | 1 | O(nm) |
| 38–40 — перебор клеток | O(1) | n · m | O(nm) |
| 41–42, 53, 55 — запуск DFS | O(1) | число островов ≤ nm | O(nm) |
| 56–59 — извлечение из стека | O(1) | ≤ n · m (каждая клетка один раз) | O(nm) |
| 60–63 — проверка соседей | O(1) | 4 · (число извлечений) ≤ 4nm | O(nm) |
| 64–65 — добавление в стек | O(1) | ≤ n · m | O(nm) |

**Время:** `O(nm)`. Вложенность «двойной цикл → вызов DFS» не даёт `O((nm)²)`: работа DFS суммарно по всем
вызовам ограничена `4nm` благодаря массиву `visited`.
**Память:** `visited` (`nm` булевых) + `stack` (`nm` чисел), это `O(nm)`. Стек вызовов `O(1)`, потому что
DFS итеративный. Рекурсивная версия использовала бы стек вызовов глубиной до `nm` и упала бы со
`StackOverflowError` (проверено тестом `shouldHandleLargeSolidGridWithoutStackOverflow` на матрице `1000 × 1000`).
