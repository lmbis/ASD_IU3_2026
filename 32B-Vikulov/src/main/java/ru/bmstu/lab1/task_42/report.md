# Задача 42. Вставка элемента в отсортированный массив

**Студент:** Викулов Петр, ИУ3-32Б · **ЛР 1** · **Баллы:** 2 · **Решение:** [`InsertSorted.java`](InsertSorted.java) · **Тесты:** [`InsertSortedTest.java`](../../../../../../test/java/ru/bmstu/lab1/task_42/InsertSortedTest.java)

## Условие

**Вход:** отсортированный по неубыванию массив из n целых чисел и число x.  
**Выход:** массив длины n + 1, в который x вставлен на правильную позицию.  
**Требование:** использовать бинарный поиск для нахождения позиции.  
**Сложность:** средняя

## Формат ввода-вывода

- **Ввод:** `n`, `n` чисел по неубыванию, затем `x`. Числа разделяются пробелами или переводами строк.
- **Вывод:** массив длины `n + 1` с `x` на правильной позиции.

Пример запуска:

```text
ввод:
2
1 3
2

вывод:
1 2 3
```

## Идея решения и выбор структуры данных

Позиция вставки ищется **бинарным поиском** (требование условия), а именно поиском верхней границы
(`upperBound`): нужен первый индекс, где элемент строго больше `x`.

Инвариант поиска: все элементы левее `low` не больше `x`, а все элементы начиная с `high` больше `x`.
Каждая итерация вдвое сокращает отрезок `[low, high)`. Когда он становится пустым, `low` и есть позиция.
Середина считается как `(low + high) >>> 1`, это защищает от переполнения при больших индексах.

После этого создаётся массив длины `n + 1`. Два вызова `System.arraycopy` копируют элементы до и после позиции,
а между ними записывается `x`. Массивы в Java фиксированной длины, поэтому новый массив неизбежен, и
копирование `O(n)` определяет итоговую сложность.

Верхняя граница выбрана, чтобы равный элемент вставлялся **после** уже существующих равных. Так вставка
сохраняет порядок поступления.

## Асимптотика — [`InsertSorted.java`](InsertSorted.java#L26-L56)

```java
27:        int position = upperBound(sorted, value);
28:        int[] result = new int[sorted.length + 1];
29:        System.arraycopy(sorted, 0, result, 0, position);
30:        result[position] = value;
31:        System.arraycopy(sorted, position, result, position + 1, sorted.length - position);
...
47:        while (low < high) {
48:            int mid = (low + high) >>> 1;
49:            if (sorted[mid] <= value) {
50:                low = mid + 1;
51:            } else {
52:                high = mid;
53:            }
54:        }
```

| Строки | Стоимость | Раз | Вклад |
|--------|-----------|-----|-------|
| 47–53 — бинарный поиск | O(1) | ⌈log₂(n + 1)⌉ | O(log n) |
| 28 — выделение | O(n) | 1 | O(n) |
| 29 + 31 — копирование | position + (n − position) = n | 1 | O(n) |
| 30 | O(1) | 1 | O(1) |

Число итераций строк 47–53: длина отрезка `high − low` каждый раз уменьшается как минимум вдвое
(строки 50 и 52), начиная с `n`. После `⌈log₂(n + 1)⌉` шагов она становится нулём.
**Время:** `O(log n) + O(n) = O(n)`. Доминирует копирование: ответ имеет длину `n + 1`, и быстрее его не
построить. Бинарный поиск по условию заменяет линейный поиск позиции (`O(n)`), а сама позиция
находится за `O(log n)`.
**Память:** массив `result` длины `n + 1` (ответ), остальное `O(1)`.
